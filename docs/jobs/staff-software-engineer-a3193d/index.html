About Our Products ApartmentIQ is the all-in-one data platform powering smarter decisions across multifamily - covering 40M units with daily property and market intelligence used for surveys, research, and revenue management. We're trusted by 65% of the NMHC Top 50. MavenAI, delivers AI-powered marketing automation built by industry experts and integrated directly with property management systems, serving over 2M units. The Role Our customers use ApartmentIQ to decide what to charge for real apartments. That number comes out of a pipeline you would own: data pulled from the property management systems that run the industry, fed through demand and renewal models, and surfaced as pricing recommendations that get acted on the same day. We're hiring a staff-level engineer to own that path end to end. It's a wide role by design - Python for the ML and ingestion services, Terraform for everything they run on, Ruby for the application layer that customers touch. Often all three in one change. If you like owning a system rather than a layer, this is that job. What You'll Be Doing • Own a system that sets rents. Demand models, renewal probability, price elasticity, compliance scoring - you'll own the pipeline that produces them and be accountable for the recommendations landing correctly. • Solve a genuinely hard data problem. Property management systems are walled gardens with inconsistent APIs and no shared identity model. Getting clean, reconciled lease and charge data out of them is the core technical challenge of this role, and we're rebuilding it from scratch right now. • Build the infrastructure you depend on. Every database, queue, and role is in Terraform, and you'll write it. No ticket to another team to get a table provisioned. • Build the orchestration layer. Ingestion, inference, and the downstream daily jobs need to run in the right order, gate on their inputs being ready, and recover cleanly when something upstream is late. You'll own that coordination layer end-to-end — today it's cron and careful timing; you'll make it a real pipeline. • Prove the numbers are right. Build out the observability and alerting across the data architecture — pipeline health, data freshness, and recommendation drift — so a bad number gets caught before a customer prices a lease against it. • Work across the whole stack, for real. Python, Terraform, and Ruby are all first-class parts of this job, not a "some exposure to" bullet. • Set the bar on AI-assisted engineering. A large and growing share of what we merge is AI-assisted. We want someone with strong opinions about how to do that well and the review judgment to enforce them. Who You Are • You want scope, not scaffolding. You're looking for a system to own outright, and you'd rather have a hard problem and autonomy than a well-defined ticket queue. • You care that it's correct. These outputs move real money. You build the checks that prove it, and you notice when a number looks wrong. • You go end to end. Empty repo to production, including the alarms, the backfill, the runbook, and the migration nobody scoped. • You raise the level around you. Your reviews make other people's code better, and work quietly moves off other plates once you're there. • You have strong opinions on AI-assisted engineering. You lean on it to ship to customers faster but you have the discipline to uphold code quality standards. Qualifications • Proven Track Record: 8+ years building and operating production systems, with real ownership of something significant. • Python Depth: Strong Python in a serverless or service context - AWS Lambda, container images, dependency and runtime management, multi-stage job orchestration. • Infrastructure as Code: Hands-on Terraform. You've stood up a production data store yourself, including the IAM, encryption, networking, and alarms around it. • Data & SQL depth: Fluent in analytical SQL and data modeling - you've built and debugged multi-stage warehouse pipelines (ours run on Redshift) and reconciled messy source data into something trustworthy. You've worked across the major database paradigms - relational, key-value/document, and search — and know what one is the best tool for the job at hand. • Ruby on Rails: You can own changes across a large Rails codebase, even if it's not where you've spent the most time. • Cloud Native: Deep AWS across Lambda, S3, SQS, Kinesis, EventBridge, DynamoDB, Aurora/RDS, Redshift, and IAM. • ML in Production: You've kept models serving correctly over time - versioning, dependency drift, feature plumbing, explainability. You don't need to have trained them. • Adaptable & Autonomous: Experience navigating a fast-paced, growth-stage environment where priorities shift and ownership is expected.
