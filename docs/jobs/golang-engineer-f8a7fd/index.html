▶︎ 團隊介紹 Golang 團隊主要負責策略無限核心交易系統的開發與維護，包含雲端策略執行平台、量化交易基礎設施、低延遲交易引擎以及各項交易相關服務。 除了業務邏輯的開發與維護之外，我們也持續與 SRE 團隊合作，優化系統架構與可觀測性，例如導入 OpenTelemetry、Prometheus Metrics、分散式追蹤、效能監控與容量規劃，確保交易系統在高併發環境下仍能維持穩定與低延遲。 身為 Golang 團隊的一員，你會感受到我們的團隊文化是： ☑ 比起單打獨鬥，我們更重視主動溝通 每日 Standup 中，大家會清楚說明目前負責的工作內容與進度，讓團隊能快速掌握系統現況，提升彼此對整體架構與業務的理解，也能及早發現潛在風險與依賴關係。 ☑ 比起追逐 Deadline，我們更重視明確的 Delivery 每個 Sprint 開始前，我們會清楚定義交付成果與驗收標準，並在 Sprint 結束時分享成果與技術設計。透過持續累積高品質的交付成果，讓產品與系統穩定成長。 ☑ 比起 Top-Down 指派任務，我們更重視共同規劃與決策 團隊會透過 OKR 與 Roadmap 對齊公司目標，讓每位成員理解專案背後的商業價值，也鼓勵大家主動提出改善建議與技術方案，讓個人成長與產品發展同步前進。 ☑ 比起沈默接受，我們更重視有價值的討論 我們鼓勵不同觀點的碰撞與交流。在討論中，先對齊問題背景與需求，再討論技術方案與實作細節，讓決策建立在充分理解與共識之上。 ☑ 比起立即開始寫程式，我們更重視完整的系統分析 無論是新功能開發或架構優化，都會先進行需求分析、系統設計與風險評估，明確定義模組邊界與擴充方向，降低重工與技術債產生的機率。 ☑ 比起只追求功能完成，我們更重視設計品質 在量化交易與低延遲系統中，每個設計決策都會影響效能與穩定性。我們重視技術方案背後的取捨，理解風險、掌握限制，並持續優化系統品質。 ☑ 比起維持現狀，我們更重視持續改善 無論是開發流程、Code Review 機制、PR 顆粒度、測試策略或技術債管理，我們都會定期檢視與優化，透過持續反思與調整，打造更好的工程文化。 ☑ 比起單純的同事關係，我們更重視夥伴關係 除了專案合作之外，我們也樂於分享生活、交流技術、討論市場與投資、研究新工具與架構。希望打造一個彼此信任、共同成長的團隊環境。 ▶︎ 工作內容 身為團隊的 Golang Engineer，我們期待你： ☑ 能夠獨立負責專案，從需求釐清、系統分析、技術設計、任務拆分到上線規劃，推動專案順利落地。 ☑ 能夠主動發掘系統中的效能瓶頸與技術債，提出改善方案並推動執行。 ☑ 能夠參與量化交易平台、策略執行引擎與低延遲交易系統的架換設計與優化。 ☑ 能夠從資料庫、快取、訊息佇列、網路通訊到系統架構層面，提出具體且可落地的技術建議。 ☑ 能夠協助建立團隊最佳實務（Best Practices），持續改善開發流程與工程文化。 ☑ 對系統穩定性與交易可靠性具有高度責任感，面對問題願意深入追查 Root Cause，直到找到真正原因。 ☑ 具備良好的技術表達與溝通能力，能夠清楚說明設計思路與技術決策。 ☑ 樂於分享知識與經驗，協助團隊成員共同成長。 ☑ 提供高品質且可維護的程式碼，包括良好的命名、模組化設計、完善測試以及清晰的介面設計。 ☑ 能與 PM、前端、QA、SRE 等不同團隊密切合作，共同打造穩定且高效能的交易平台。 ▶︎ 條件要求 【 必備技能 】 學歷：資訊工程、資訊管理學士以上學位或相關科系背景。 Golang 開發經驗： 具備 2 年以上實務 Golang 開發經驗，熟悉 Go 語言核心機制與慣用法（Idiomatic Go）。 熟練掌握 Goroutine、Channel、Context 等高併發與非同步處理機制。 具備撰寫高覆蓋率單元測試（Unit Test）與整合測試（Integration Test）的習慣與經驗。 容器與雲端技術： 熟悉 Docker 容器化技術，能獨立編寫高效、安全的 Dockerfile 並優化映像檔大小。 熟悉 Docker Compose 在本機開發與測試環境的集成配置。 了解網頁伺服器與反向代理（如 Nginx、Envoy）的基礎配置。 系統與網路基礎： 具備 Linux 系統操作與 Shell Script 基本運用的能力。 熟悉 Git 版本控制流（如 Git Flow / GitHub Flow）及 Code Review 流程。 了解 RESTful API、gRPC 等通訊協定設計與開發。 資料儲存： 熟悉關聯式資料庫（如 PostgreSQL, MySQL）並了解 SQL 語法優化。 熟悉快取機制（如 Redis）的應用場景。 【 加分技能 】 熟悉 Go 進階特性與底層機制（如 Memory Allocator, Garbage Collection 運作原理）。 具備 Kubernetes (K8s) 實務部署、維護或服務遷移經驗。 熟悉 CI/CD 工具（如 GitHub Actions, GitLab CI, Drone）並具備自動化建置流程規劃經驗。 具有微服務架構（Microservices）設計經驗，並了解分散式追蹤與服務治理。 具備訊息佇列（如 Kafka, RabbitMQ）的實務開發經驗。 具有金融、量化交易系統或高併發、低延遲系統之相關開發經驗。 • 加入後 ➜ 1~3 個月內，你將會： • 熟悉團隊開發流程與工程文化 • 建立完整開發環境 • 了解策略無限整體產品架構與核心業務流程 • 透過新手專案熟悉 Codebase 與開發流程 • 修復一項技術債或效能問題 • 參與系統分析會議與技術討論 • 熟悉策略執行流程、交易串接機制與系統架構 ➜ 3 個月後，你將會： • 負責核心交易服務與關鍵模組開發 • 參與低延遲交易系統與量化平台架構優化 • 主導或協助推動重要專案 • 參與團隊 OKR 與技術 Roadmap 規劃 • 解決複雜的效能與架構問題 • 成為專案或技術領域的主要負責人 • 持續推動系統穩定性、可觀測性與開發效率提升
