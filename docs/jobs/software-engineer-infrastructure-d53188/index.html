About E2B E2B is a fast-growing Series A startup with over $37M in funding and 9-figure revenue. We are building the Agent Cloud and power the infrastructure behind AI labs and some of the most widely used consumer and enterprise agents, including Manus, Genspark, Lindy, Groq, and Artificial Analysis. Our team includes original authors of Firecracker, the AWS microVM technology powering Lambda, along with alumni of Cognition, JetBrains, Zapier, and Wish. About the role E2B has started billions of Firecracker sandboxes across regions on Google Cloud, AWS and Azure, and single customers now ask for 100,000 of them running at once. The control plane behind that is a set of Go services backed by Postgres and Redis, deployed on Kubernetes and managed through GitOps. Your job will be to own how the platform fits together: the API and the proxy layer that routes traffic to sandboxes, our Kubernetes infrastructure across clouds and regions, and the infrastructure that makes every region and cloud run the same code. You'll work closely with our systems engineers, who own Linux, the software that runs sandboxes on each host, and sandbox networking, and with the engineers building the product on top of the control plane. Our runtime is open source at github.com/e2b-dev/runtime, and the api service and the proxy are good places to see what you'd work on. Responsibilities include: • Designing and building Go services and APIs: new endpoints, gRPC and OpenAPI contracts, and the data models behind them • Building and evolving the edge proxy and the routing state behind it, so traffic stays correct as sandboxes pause, resume and move between hosts • Scaling the API and the Redis and Postgres behind it to hundreds of thousands of concurrent sandboxes per region: query and schema design, caching, sharding and migrations under load • Writing the Kubernetes automation that scales the platform with demand: provisioning capacity ahead of load spikes and draining long-lived nodes without disrupting running sandboxes • Implementing placement across machine families and CPU generations on multiple clouds, so a resumed sandbox always lands on a host that can restore it • Building the Terraform modules, Helm charts and Argo CD configuration that make a new region or cloud fast and repeatable to stand up • Building the metrics, tracing and alerting for the services you own • Making sure self-hosted and enterprise deployments run what we run (we're open source) • Being on call for the platform you build, alongside the rest of the platform team This role requires a high amount of ownership. You'll write the code and the design docs for the hardest changes in your area, and ship every day. If words like control plane, Kubernetes, L7 routing, GitOps, gRPC contracts, or multi-region sound exciting to you, we want to hear from you! What we're looking for • Experience owning a large-scale distributed system end to end: building it, running it in production across regions, and being the person called when it breaks • Strong Go: you build services and ship fixes in services you did not write • Experience operating large-scale Kubernetes clusters in production, including controllers, operators and node lifecycle management • Infrastructure as code and GitOps, for example Terraform and Argo CD, with deep experience on at least one of GCP, AWS or Azure; we run on all three, and you don't need to know them all • API and data design: service contracts and Postgres data models (gRPC, OpenAPI) that stay backward compatible, with schema changes and migrations under load on a primary that cannot go down • Solid Linux and networking fundamentals: enough to debug a host under load and reason about L4/L7 traffic, load balancing and connection draining • Excited to work in person from San Francisco • Comfortable with our code and infrastructure being public We expect this experience will often come from around five or more years of relevant work, but the depth of what you've built matters more than a specific number. Bonus points for: • Building reliable distributed APIs: idempotency, leases and backpressure • Multi-account cloud organizations, such as AWS Organizations and GCP folder hierarchies • Shipping infrastructure that customers run themselves • Familiarity with Firecracker, KVM or how VM workloads behave on shared hosts • Contributions to Kubernetes or other CNCF projects What it’s like to work at E2B We’re a fast-growing startup with in-person (4 days on-site, 1 day WFH) offices in San Francisco and Prague, Czech Republic. We already generate 9-figure revenue and work directly with top-tier AI companies like Manus, Genspark, Lindy, Groq, Artificial Analysis and other exciting teams pushing the frontier of AI. We offer healthcare, vision, and dental insurance, unlimited PTO, 401k, and a variety of perks for in-office employees.
