About Plane Plane's mission is to build the infrastructure the world's work runs on. Every organization runs on three things: the projects it's driving, the knowledge it keeps, and the requests it fields. Plane brings all three into one open, adaptable platform: simple enough for any team to adopt, dependable enough for organizations to build on. And we are building it for a future where humans and AI agents do that work together. Plane began in public on GitHub at the end of 2022. Since then it has grown into a work management platform used by teams around the world: 61,000+ stars, 6,200+ forks, and a contributor community that reads our code and files our issues. Organizations run Plane as a managed Cloud service, on their own infrastructure, or inside fully isolated environments. Building in the open keeps us close to users and raises the standard for everything we ship. Plane is the #1 work infrastructure in aerospace, defense, financial services, and other regulated industries: organizations whose requirements for control, auditability, and data residency rule most software out. When the strictest buyers pick a system of record, that choice means something. Adoption is growing fastest on Plane Cloud and in sovereign clouds, deployments that keep everything inside a country's own borders and rules. Plane is backed by top investors and built across San Francisco, London, and Hyderabad. We work in tightly knit teams, stay close to users, and care about the visible product as much as the unglamorous details that make software dependable. People own problems end to end, and we add process only when it helps the work. Humans and agents We believe the next decade of work will be done by humans and AI agents together. Not agents replacing people, and not a chat window bolted onto software built for humans clicking around, but both working in one system of action, where an agent's work is as visible and as accountable as a person's. Most software treats AI as a feature. We treat agents as a kind of worker, and that changes what the system underneath has to be. Agents are only as good as the context they can see and the state they are allowed to change, so shared context, explicit state, durable history, and accountable action are not items on our roadmap. They are the product. Plane is built so that when an agent acts, the humans responsible can see what happened, why, and on whose authority, and the record survives. This is what the infrastructure is for: making the future where humans and agents work together useful, legible, and fully within the organization's control. Every role at Plane is some part of building that. About the role Plane runs as a managed Cloud service, on customers' own infrastructure, and inside isolated environments that never touch the internet. Adoption is growing fastest on Plane Cloud and in sovereign clouds, and that growth is why this role exists. Every one of those environments is somewhere our releases have to install, upgrade, and stay healthy, mostly on machines we will never log into. You will own the infrastructure behind Plane Cloud and the path that gets one codebase into every self-hosted environment: Terraform, Kubernetes, CI/CD, and the alerts that tell us something broke. You will work with backend and frontend engineers in San Francisco and Hyderabad, and directly with customers' platform teams when a self-hosted install misbehaves. What you'll do • Own Plane Cloud's infrastructure on AWS and Kubernetes: defined in Terraform, deployed through GitOps with Argo CD and Rancher Fleet, and sized so capacity and cost keep pace with usage. • Build and run the CI/CD pipelines that ship one codebase to Plane Cloud and to the Docker Compose and Kubernetes deployments self-hosted customers run. • Design installs and upgrades that work in places you will never log into: customers' own clouds, sovereign clouds, and air-gapped networks with no internet connection. • Run observability across the platform, with Datadog and the LGTM stack for metrics, logs, and traces, so we hear about degradation before a customer does. When an alert fires, you respond. • Own infrastructure security: access controls, vulnerability management, and the findings Wiz surfaces. Regulated industries choose Plane for control and auditability, so this work is part of what customers buy. • Work daily with backend and frontend engineers in San Francisco and Hyderabad, with customers' platform teams, and with community members whose self-hosted issue reports land in public on GitHub. • Debug problems that cross every layer. A self-hosted ticket can turn out to be a reverse proxy, a Postgres setting, a firewall rule, or a bug in our own code. You will chase it to the real cause, then turn the fix into a default or a doc so the next customer never hits it. What you'll bring You have run production infrastructure on AWS or GCP, defined as code in Terraform or similar, and you can walk us through an outage you handled and what you changed afterwards. • You have operated Kubernetes clusters in production, not only deployed to them, and you have packaged applications with Docker and Docker Compose. • You have built CI/CD pipelines (GitHub Actions, GitLab CI, Jenkins, or similar) that a team shipped through every day, and you automate the rest in Bash, Python, or Go. • You follow a problem past the edge of your job title. You have traced an issue into networking (DNS, TLS, firewalls, VPNs, load balancers), a reverse proxy like Nginx or Caddy, or the Postgres and Redis behind an application, and you can tell us how you found it. • You have set up monitoring and alerting (Prometheus, Grafana, Datadog, or similar) that caught a real problem before users did. • You have put infrastructure security into practice: least-privilege access, secrets management, and patching vulnerabilities on a schedule rather than after an incident. Nice to haves • You have contributed to Plane, run it self-hosted, or contributed to an open-source infrastructure tool people rely on. • You have deployed into regulated, sovereign, or air-gapped environments, where pulling an image from the internet was not an option. • You have run GitOps with Argo CD or Rancher Fleet, or managed many clusters with Rancher. • You have operated RabbitMQ or Kafka in production. • You have used AI agents in operations work, and you have opinions about what an agent should be allowed to change on real infrastructure. The teams are deeply connected enough that credit and responsibility both find you fast. That is some pressure. Mostly it is the fun part.
